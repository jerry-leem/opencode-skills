# 여러 에이전트로 반복 수행하기

이 절차는 실제 환경이 하위 에이전트를 제공하고 위임이 허용된 경우에만 적용한다.
역할 이름은 책임을 설명하며 OpenCode에 해당 이름의 에이전트가 설치되어 있다는 뜻은 아니다.
사용 가능한 에이전트와 도구를 먼저 확인하고 제공되는 호출 방식만 사용한다.

## 책임과 소유권

오케스트레이터 한 명이 목표, 반복 횟수, 중단 판단, `GOAL.md`, `PROGRESS.md`, `DECISIONS.md`의 기록을 소유한다.
다른 에이전트는 상태 파일을 동시에 수정하지 않고 결과와 증거를 전달한다.

| 역할 | 맡길 작업 | 반환할 내용 |
| --- | --- | --- |
| Planner | 현재 상태를 바탕으로 단일 목표 선택 | 목표, 범위, 검증 방법 |
| Researcher | 필요한 코드·문서 조사 | 근거 경로, 확인된 사실, 미확인 사항 |
| Developer | 지정 범위의 구현 | 변경 파일, 동작 변화, 검증 결과 |
| Tester | 실제 실행과 실패 재현 | 실행 위치, 명령, 결과, 증거 |
| Reviewer | 요구사항과 구현의 독립 검토 | 발견 사항과 근거, 잔여 위험 |

각 위임에는 목표, 허용된 파일·행동, 완료 조건, 검증 방식, 반환할 증거를 명시한다.
공유 작업 공간의 다른 변경을 되돌리지 말고 충돌 시 오케스트레이터에게 알리도록 한다.
같은 파일을 여러 구현자에게 동시에 맡기지 않는다. 독립적인 조사나 서로 겹치지 않는 구현만 병렬화한다.

## 구현과 검증 분리

가능하면 구현자와 검증자를 분리한다. 검증자에게 실제 요구사항, 변경 내용, 실행 환경을 주고 원하는 판정을 유도하지 않는다.
도구가 없거나 위임 비용이 이점보다 크면 한 에이전트가 검증을 수행하고 독립 검토가 없었다고 명시한다.

하위 에이전트의 완료 선언만으로 완료 항목을 체크하지 않는다.
오케스트레이터는 반환된 증거를 확인하고, 변경을 통합한 실제 상태에서 필요한 검증을 수행한다.
하위 작업 재시도도 상위 반복·실패 제한에 포함한다. 별도의 무제한 재시도 예산을 만들지 않는다.

중단 조건에 도달하면 새 위임을 멈추고 실행 중 작업에 중단을 전달한다.
안전하게 끝나거나 중단된 작업의 결과를 회수하고 미완료 작업과 변경 경로를 기록한다.
진행 중인 에이전트를 남긴 채 전체 작업을 완료했다고 보고하지 않는다.
